DOCUMENTACION DEL FLUJO Y ARCHIVOS - PulseChat
Fecha de referencia: 6 de mayo de 2026

1) RESUMEN DEL PROYECTO
- Plataforma: iOS (SwiftUI + SwiftData + Firebase)
- Arquitectura: MVVM con capas (Views, ViewModels, Repositories, Services, Persistence, Core)
- Flujo principal: Login/Registro -> Lista de chats -> Detalle de chat
- Datos: Firebase Auth + Firestore como origen principal; SwiftData como cache local
- Estado: carga, error, vacio, offline
- Seguridad: Keychain para userId; Firebase Auth para sesion
- Permisos: camara, galeria, ubicacion y notificaciones (solicitados al inicio)
- Tema: system/light/dark persistente
- Idiomas: en/es/system con Localizable.strings
- Build: Xcode 15+ con iOS 17+

2) FLUJO FUNCIONAL DETALLADO (PASO A PASO)
2.1 Inicio y configuracion
- PulseChatApp inicia Firebase (FirebaseApp.configure) y crea el ModelContainer de SwiftData.
- Se configura DependencyContainer con SwiftDataStack (repositorios listos).
- Se aplica idioma con LanguageManager (override de Bundle).
- Se proveen objetos globales via environment: AppState y NetworkMonitor.

2.2 Permisos al iniciar
- RootView dispara PermissionManager.requestAllPermissions() al cargar.
- Se solicitan: ubicacion, camara, fotos y notificaciones.

2.3 Autenticacion
- AuthViewModel intenta restaurar sesion al iniciar (AuthRepository.currentUser).
- Si existe usuario, RootView navega a ChatListView.
- Si no existe usuario, RootView muestra LoginView.

2.4 Login/Registro
- LoginView permite cambiar entre login y register.
- LoginView llama a AuthViewModel.login o AuthViewModel.register.
- AuthRepository usa Firebase Auth para crear o iniciar sesion.
- Se crea/actualiza documento de usuario en Firestore.
- Se guarda userId en Keychain.

2.5 Lista de chats
- ChatListView carga chats en onAppear y en pull-to-refresh.
- ChatListView muestra estados:
  - LoadingView cuando isLoading.
  - ErrorView si hay error.
  - EmptyStateView si no hay chats.
- NetworkMonitor muestra banner offline si no hay conexion.
- Navegacion:
  - Tap en chat -> ChatDetailView.
  - Boton buscar -> SearchUserView.
  - Boton logout -> AuthViewModel.logout.

2.6 Busqueda de usuarios y creacion de chat
- SearchUserView consulta usuarios (Firestore) por emailLowercase.
- Se excluye el usuario actual.
- Al elegir un usuario, se crea chat si no existe.
- Se navega a ChatDetailView con el chat creado/encontrado.

2.7 Detalle del chat
- ChatDetailView carga mensajes al aparecer.
- Muestra mensajes en ScrollView con burbujas.
- Permite:
  - Enviar texto
  - Adjuntar imagen (camara o galeria)
  - Editar mensajes propios
  - Eliminar mensajes propios
- Si se adjunta imagen sin texto, el mensaje se guarda localmente (SwiftData) y el ultimo mensaje del chat usa el fallback de AppStrings.imageMessageFallback.
- Se guardan fechas de ultimo visto por chat en UserDefaults (pulsechat.lastSeen.<chatId>).
- Si hay mensajes nuevos desde la ultima vista, se dispara notificacion local.

2.8 Manejo offline
- NetworkMonitor detecta conectividad y la UI muestra un banner.
- ChatRepository intenta sincronizar con Firestore.
- Si falla y existen datos locales, retorna los datos de SwiftData.

3) ARQUITECTURA Y CAPAS
- Views: pantallas SwiftUI y componentes de UI.
- ViewModels: estado de UI, acciones y coordinacion con repositorios.
- Repositories: acceso a Firebase/SwiftData; orquestan sincronizacion.
- Services: API REST opcional, Firebase async wrappers, utilidades.
- Persistence: SwiftData con entidades y relaciones.
- Core: constantes, DI, seguridad, extensiones, tema y utils.

4) CONSUMO DE DATOS
- Firebase Auth: login/registro por email y password.
- Firestore: usuarios, chats y mensajes.
- REST opcional: APIClient/MockAPIClient (no conectado al flujo principal).

5) PERSISTENCIA LOCAL
- SwiftData almacena UserEntity, ChatEntity, MessageEntity.
- Cache local se actualiza desde Firestore y se consulta si hay offline.
- UserDefaults almacena lastSeen por chat.

6) SEGURIDAD
- KeychainManager guarda userId y token (token no se usa en flujo actual).
- Firebase Auth maneja la sesion.

7) PERMISOS Y NOTIFICACIONES
- PermissionManager solicita:
  - Camara (AVFoundation)
  - Galeria (Photos)
  - Ubicacion (CoreLocation)
  - Notificaciones (UserNotifications)
- NotificationManager solicita autorizacion y envia notificaciones locales.
- Importante: se deben definir los usage descriptions en el Info.plist del target en Xcode.

8) i18n Y TEMA
- Idiomas: en/es/system con Localizable.strings y LanguagePickerView.
- Tema: system/light/dark con ThemePickerView y AppStorage.

10) CUMPLIMIENTO DE REQUISITOS MINIMOS (MAPEO RAPIDO)
- Codigo: Swift iOS.
- Arquitectura: MVVM + capas separadas.
- Navegacion: lista <-> detalle, busqueda -> detalle.
- Consumo de datos: Firebase Auth + Firestore; REST opcional.
- Manejo de errores y carga: isLoading + ErrorView + EmptyStateView.
- Conectividad: NetworkMonitor + fallback a datos locales.
- Persistencia local: SwiftData.
- Seguridad: Keychain + Firebase Auth.
- Permisos: camara/galeria/ubicacion/notificaciones.
- Documentacion: README.md y README1.md.

- Extras: tema persistente, i18n, notificaciones, accesibilidad basica.
